# Revisión institucional y QA

Fecha: 11 de noviembre de 2026. Base: `35aee55`.

## Resultado de diseño

- Inicio centrado en la asociación: propósito, fotografía real, Coro Esperanza inmediatamente después de la portada, tres líneas de trabajo, transparencia, CDE, documentos, Conecta y colaboración.
- `/asociacion` con misión, visión, trabajo, beneficiarios, principios, historia, documentos y formas de apoyo. Menos tarjetas repetidas y mayor jerarquía de lectura.
- Conservadas las fotografías elegidas, PayPal, carrusel de actividades, biblioteca en lista, lector, blog y CDE.
- Sin estadísticas de impacto, testimonios ni alianzas inventadas. Los datos bancarios históricos conservan advertencia de confirmar vigencia y titular antes de transferir.
- Información institucional contrastada con el registro de [Agenda 2030 Puebla](https://agenda2030.puebla.gob.mx/sociedad/comunidad-critica-de-escultismo-popular-a-c). Su presencia en ese registro no se presenta como aval gubernamental. No se atribuye información a Facebook que no pudo consultarse.

## Hallazgos y correcciones

| Hallazgo observado | Corrección |
| --- | --- |
| Navbar cortado a 1024 px | Dos filas en tablet, una fila en escritorio amplio; hamburguesa solo debajo de 768 px |
| Contacto del footer se superponía con Legal | Reparto de columnas y saltos de texto corregidos |
| PDF público devolvía 200 pero el navegador lo bloqueaba en iframe | CSP permite exclusivamente el directorio público `content-assets` del proyecto configurado; conserva `frame-ancestors 'none'`, `object-src 'none'` y X-Frame-Options |
| URL antigua real de WordPress devolvía 404 | 312 redirecciones permanentes al artículo correspondiente; además `/historia` y `/escultismo` |
| Cuatro artículos importados tenían varios H1 | Encabezados H1 del cuerpo normalizados a H2, conservando título principal |
| Retorno de login admitía destinos externos | Validación compartida en formulario y callback |
| Faltaba salto al contenido | Enlace visible al recibir foco y destino enfocable en cada main |
| Menú móvil no gestionaba completamente teclado/foco | Apertura enfoca primer enlace; Escape devuelve foco al botón; navegación acotada |
| Carrusel podía reanudarse tras una pausa manual | Pausa manual separada del hover, respeta movimiento reducido |
| Carga continua dependía solo del observador | Botón alternativo y reobservación tras cargar más |
| Una configuración ausente de postales podía impedir generar inicio | Estado de bienvenida seguro, sin caída de la página |
| OTP antiguo tenía una ruta de verificación todavía accesible | Ambos endpoints se cierran fuera del prototipo local explícito |
| Crear correo existente cambiaba contraseña sin distinguir edición | Respuesta 409; cambio deliberado desde edición |
| Correo fallido podía ocasionar limpieza de portada ya guardada | Se separa la propiedad del archivo y se controla el fallo de correo |
| Aprobar repetidamente renovaba fechas | Solo se moderan pendientes; 409 si ya se revisó o no existe |
| Fotos de postales configuradas como públicas antes de moderación | Código con URLs firmadas; migración de bucket privado preparada, no aplicada remotamente |
| Políticas antiguas daban escritura Storage a cualquier autenticado | Migración restrictiva preparada, no aplicada remotamente |

## Pruebas realizadas

- Exploración HTTP de las **426 páginas** publicadas en sitemap antes de la intervención: todas devolvieron 200. **120 imágenes** revisadas devolvieron 200 con tipo imagen.
- `robots.txt` y `sitemap.xml` accesibles. No apareció `localhost` en el HTML público analizado. No se confirmó el antiguo problema de canonical a localhost en la versión auditada.
- Se comprobaron título, descripción, canonical, Open Graph, Twitter, H1, idioma y cabeceras por página mediante `npm run qa:public`.
- 12 pruebas automatizadas aisladas, sin modificar Supabase: redirecciones, sanitización, CSP, foco, orden del inicio, OTP, correo, creación duplicada, esquema ausente, enlaces firmados y moderación repetida.
- Compilación y revisión de tipos. Aviso no bloqueante: Next 16 anuncia retirar soporte React 18 en Next 17. No se hizo una actualización mayor mezclada con esta revisión.
- Vista en navegador integrado Chromium a 320, 390, 768, 1024 y 1440 px; sin desbordamiento horizontal en las pantallas medidas. Se revisaron inicio, asociación, footer, blog y donación.
- Menú móvil abre enfocando Inicio y Escape lo cierra devolviendo foco. Búsqueda sin resultados y restablecimiento del blog; carga de más de las 12 entradas iniciales.
- Carrusel: pausa persistente tras avanzar; enlace PayPal coincide con el proporcionado. No se realizó ningún pago.
- Diagnóstico Supabase de solo lectura: los resultados y pasos están en [la guía de operación](SUPABASE-OPERACION-2026-11-11.md).

## Alcance y pendientes reales

- No se dispone de sesiones reales de Safari, Firefox, Edge, Samsung Internet ni dispositivos físicos; el cambio de tamaño no equivale a certificar esos navegadores.
- No se ejecutó Lighthouse ni se obtuvieron métricas de campo LCP/INP/CLS. No se inventa una puntuación de rendimiento o cumplimiento WCAG completo.
- No se probaron inicios de sesión con contraseñas reales, alta remota de cuentas, publicación real de artículos, recepción de correo ni pagos. Las pruebas de seguridad de los handlers usan servicios simulados y no sustituyen la aceptación autenticada en ensayo.
- La CSP conserva `unsafe-inline`, necesario en la arquitectura actual; una política con nonces requiere trabajo separado.
- Conecta necesita completar configuración de esquema, almacenamiento privado, sesión y correo. Falta validar un límite distribuido de intentos y una cola de reintentos de correo.
- La biblioteca editorial y las fotos del blog siguen siendo públicas; borrador no significa archivo confidencial.
- La recuperación de WordPress aquí preserva archivos y enlaces ya migrados; no significa haber recuperado todos los respaldos del servidor antiguo.

## Reproducir la revisión

```sh
npm ci
npm test
npm run typecheck
npm run build
npm run qa:public -- https://www.escultista.org
```

Configura las variables del entorno sin poner secretos en el repositorio. `QA_REPORT=/ruta/absoluta/reporte.json` permite guardar el detalle del barrido público. El escáner usa cuatro solicitudes concurrentes y no envía formularios.
